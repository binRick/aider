# Plan: Agentic tool-calling loop for aider + GitLab integration (conaider-compatible)

> **Status: planning document only — no code has been changed yet.** This is the roadmap for implementing the agent mode and GitLab integration in this fork. All file/line references were verified against this tree (v0.86.3.dev, HEAD 5dc9490bb) and against `../conaider` on 2026-07-01.

## Context

aider is the only approved open-source AI harness for a company project, so it must be extended (not replaced) to behave like a tool-calling agentic harness (Claude Code-style multi-turn loop) instead of its single-shot "parse text edit blocks" design. Target runtime is a small local model via Ollama (`ollama_chat/gemma3`). The direct consumer is **conaider** (`../conaider`), an air-gapped docker-compose sandbox (GitLab CE + Ollama + docs-mcp + aider TUI); vanilla aider inside conaider will be replaced with this fork. Second task: GitLab issue-to-MR integration — completing a gap conaider already has (it auto-pushes session branches; MR creation is manual today). Deliverables: (1) agent mode behind a flag, demonstrated end-to-end on a real repo with gemma3; (2) GitLab issue-to-MR; (3) a detailed integration `.md` in this repo so offline conaider can adopt the improved aider.

**This repo** (`aider-binrick`) is byte-identical to upstream Aider-AI/aider at v0.86.3.dev (verified: 0 ahead/0 behind, HEAD 5dc9490bb). New work is the fork's first divergence → isolate it in new modules; keep shared-file diffs small and upstream-idiomatic.

## Decision-critical findings (verified by recon + adversarial review)

### A. Native tool-calling with gemma3 is impossible — dual-mode adapter required
- Ollama's stock gemma3 **hard-rejects** `tools=`: HTTP 400 `"…/gemma3 does not support tools"` (no `tools` capability; Ollama issue #9941 open). Google: Gemma 3 has no tool tokens; function calling is **prompt-based** (fenced ` ```tool_code ` blocks parsed by the caller).
- litellm (pinned 1.82.3, requirements.txt:184) passes `tools=` through with **no fallback** → hard error, not degradation. 1.82.3's `ollama_chat` also pops `tool_choice` and **drops assistant-history `tool_calls` on resend** (breaks multi-turn native loops). Ollama's OpenAI-compatible `/v1` endpoint (litellm `openai/` + `api_base`) avoids those transforms — **but** the `/v1` path bypasses aider's `num_ctx` handling entirely (`is_ollama()` matches only `ollama*/` prefixes, models.py:931-932, 1012-1014) and `/v1` has no per-request `num_ctx` → silent truncation at server default unless `OLLAMA_CONTEXT_LENGTH` is set on the Ollama service (or a Modelfile bakes `num_ctx`). Native path therefore **requires that server-side knob**, documented and spike-verified.
- Evidence on protocols: Cline/Roo migrated text→native for tool-trained models (~10–30% text failure vs ~100% native); aider's own benchmark shows code-in-JSON degrades edits; gemma3 tool finetunes reach only ~88% at 12B.
- **Conclusion**: `ToolCallAdapter` with `native` | `text` | `auto` modes (auto = probe Ollama `/api/show` capabilities, else downgrade once on the deterministic 400, with a warning). Text mode is the gemma3 path. Non-Chinese-model constraint (from conaider) → native-mode fallback candidates: `llama3.1`, `gpt-oss:20b`, `granite4.1`, `gemma4` — never qwen.

### B. aider internals — what exists vs what's new (key refs)
- `run_one()` (base_coder.py:924) wraps `send_message()` (:1419) in a reflection loop (`max_reflections=3`, :101). `send_message` is called polymorphically only from run_one (:934, `list(...)`) and run_stream (:862, `yield from`) → **an AgentCoder subclass can override it**; the override must stay a **generator** and replicate: the litellm retry/backoff loop (:1449-1512), ContextWindowExceededError→exhausted handling, KeyboardInterrupt transcript repair, the finally-block cleanup (:1513-1523: mdstream finalize, spinner stop, `partial_response_content` + reasoning strip), and the post-finally `cur_messages` appends via `add_assistant_reply_to_cur_messages` (:1534). Factor the retry machinery into a helper both paths call.
- **Tool plumbing is new**: `send_completion` forces `functions[0]` + `tool_choice` (models.py:1006-1009); streaming reads only legacy `delta.function_call` (base_coder.py:1913-1923); non-streaming keeps `tool_calls[0]` only, no ids (:1850-1853). Old func coders are reference-only (deprecated RuntimeError / commented out / signature drift).
- **Edit apply is reusable**: `replace_most_similar_chunk` (editblock_coder.py:157) is pure (exact + whitespace + `...` tiers; fuzzy matching dead behind bare `return` at :183); failure-report template :84-123; `find_similar_lines` :602. Avoid `do_replace` (its `touch()` at :371 fires even in dry-run) — handle file creation explicitly under the permission gate.
- **Permissions**: `io.confirm_ask` (io.py:807) + `ConfirmGroup` (:82) + `never_prompts` (:269, deny-only, session-only) exist; shell prompts use `explicit_yes_required=True` (base_coder.py:2453-2462) which `--yes-always` cannot approve (io.py:866-867). New work = per-tool-category **policy** on these primitives.
- **Message-shape hazards**: `ChatSummary` drops `role:"tool"`/TypeErrors on `content=None` (history.py:101-107); `get_context_from_history` (base_coder.py:2369-2374) crashes on `content=None` and feeds auto-commit; `Model.token_count` swallows exceptions → returns 0 (models.py:650-656). → tool-shaped dicts live only inside the in-flight loop; stringify before any counting/summary/commit-context; treat token-count 0/exception as over-budget.
- **Streaming UI**: fresh `MarkdownStream` per assistant segment via `io.get_assistant_mdstream()` (io.py:1014); interleave with `io.tool_output` between finalized segments. Guard the verified mdstream bug: `final=True` with no new stable lines returns early (mdstream.py:200-201) before `live.stop()` (:213-217) → explicit stop on empty segments. Pretty mode yields nothing from the send generator (:1972) — never depend on yielded chunks.
- **Wiring** (from adversarial review): main.py enumerates every kwarg passed to `Coder.create` (main.py:973-1007); base `Coder.__init__` has no `**kwargs` and extra kwargs replay on `/chat-mode` switches via `original_kwargs` (base_coder.py:153-193, main.py:1165-1177) → agent params must follow the **`--auto-accept-architect` precedent** (param on base `__init__` base_coder.py:340 + threaded in main.py:1005). Batch flags are consumed in main.py (cf. `args.message` main.py:1126-1134).
- **Commit semantics trap** (from review): deferred-commit + incremental edits collide — a second edit to the same file makes `check_for_dirty_commit` (base_coder.py:2175-2189) see the agent's own first edit as dirty and fires a mid-turn `dirty_commit` (`aider_edits=False`, hash never recorded → `/undo` breaks, commands.py:573; multiple pushes in conaider). Also `allowed_to_edit` adds files to `abs_fnames` (:2222,2236) → full file content re-embedded every iteration (context blowup at 8k) + double prompting.
- **Repo map**: `ollama_chat/gemma3` has **no model-settings entry** → defaults `use_repo_map=False`, `max_chat_history_tokens=1024`; RepoMap is only built when `use_repo_map` AND `gpt_prompts.repo_content_prefix` is non-empty (base_coder.py:487-498); repo map reaches messages via `format_chat_chunks` → `chunks.repo` (:1281, 1333-1334).
- **Registration/config**: new coder = class in `coders/__init__.py` `__all__` (auto `--edit-format` choice, args.py:48-54); flags get `AIDER_*` env + yaml free (args.py:40-41); slash commands auto-discover via `cmd_*` (commands.py:276-285); batch entry `Coder.run(with_message=...)` (:876-881). Tests: `@patch("litellm.completion")`, `coder.send` monkey-patch, `InputOutput(yes=True)`, `main(..., return_coder=True)`.

### C. conaider integration surface (verified in ../conaider)
- Launches vanilla aider CLI interactively: `aider --model "$MODEL" --no-check-update "$@"` (scripts/conaider-tui.sh:245); default model `ollama_chat/gemma3` = **gemma3:4b**; installed **unpinned** via `pip install aider-chat` (Dockerfile:31; offline manifest pinned 0.86.2). Replacing aider = point that pip line at this fork (git URL / wheel in the offline bundle); keep the `aider` entrypoint + default behavior.
- `conventions/aider.model.settings.yml` (`edit_format: whole`, `use_repo_map: true`, `num_ctx: 8192`) is an **unwired template** (INDEX.md: "Template (not wired)"; no Dockerfile COPY, no `--model-settings-file` on the launch line). aider silently skips a missing settings file (models.py:1088-1089) → the integration doc must include full wiring steps + a "verify it took" note.
- **Auto-commit is load-bearing** (ephemeral clones; post-commit hook pushes); env already set: `OPENAI_API_BASE=$OLLAMA_API_BASE/v1`, `OPENAI_API_KEY=dummy`, `LITELLM_LOCAL_MODEL_COST_MAP=True`; GitLab CE in-stack with `CONAIDER_PAT` (api scope), `GITLAB_URL=http://gitlab`, `oauth2:<token>@` clone remotes, session branch pre-pushed. Air-gapped: **no runtime pip install possible** — new deps must be baked at image build. Non-Chinese models only; num_ctx 8192 typical; compose sets no `OLLAMA_CONTEXT_LENGTH`.

## Design decisions

1. **New Coder subclass `AgentCoder` (edit_format `"agent"`), logic in new modules.** The core loop (`send_message`/`run_one`/streaming) in base_coder.py is untouched; base_coder.py gets only **additive `__init__` params** for agent options (the `auto_accept_architect` precedent — switch-safe against `original_kwargs` replay), threaded through main.py's `Coder.create` call. Justification: polymorphic `send_message` seam, automatic registration/flag wiring, ArchitectCoder precedent, cheap upstream merges.
2. **Dual-mode `ToolCallAdapter`** (native | text | auto). Native mode: `tools=` + `tool_choice="auto"`, **non-streaming tool turns in MVP** (Ollama/litellm 1.82.3 streams lack reliable tool_call ids); if used against Ollama, either `ollama_chat/` (adapter rebuilds assistant tool history to dodge the 1.82.3 resend bug) or `openai/…/v1` **with `OLLAMA_CONTEXT_LENGTH` mandated server-side** and a model-metadata entry so `check_tokens` works. Text mode (gemma3 path): tools described in the system prompt; **grammar = exactly one fenced JSON header block + at most one raw payload block**; payload fences are collision-proof (longer backtick run chosen per payload, or sentinel delimiters); parser validates against the tool schema, one reformat-retry with a structured error. **Explicit done-convention**: a turn must contain either a tool block or the terminal marker (e.g. a trivial `done` tool / `FINAL:` marker) — "no block" is treated as malformed, so final-answer vs fumbled-syntax is decidable and measurable. Text-mode turns and the final answer stream; parsing happens on the completed text after reasoning-tag stripping.
3. **Tools carry actions; code payloads stay raw.** `edit_file(path, search, replace)` reuses `replace_most_similar_chunk` + the proven failure text + `find_similar_lines`; `write_file(path, content)` kept for gemma3:4b (whole-file more reliable at 4B) **with guardrails**: target must have been read this session or be new; size-aware prompt steering (write_file small files / edit_file large); payload rejected if it exceeds remaining context headroom.
4. **Permission policy layer** over `confirm_ask`: reads auto-allowed; edits prompt via `ConfirmGroup` (batch "All") unless `--agent-auto-approve-edits`; `bash` opt-in (`--agent-allow-shell`) + always `explicit_yes_required`. **Single prompting path**: the policy layer is the only prompt for edits — it pre-answers `allowed_to_edit`'s own confirm (ConfirmGroup preference) so users aren't double-prompted. Persistent policies = documented future work.
5. **Loop budgets own their state** (never `reflected_message`/`max_reflections`): iteration cap (`--agent-max-iterations`, default 20); stall guards = identical-call-in-last-N + no-progress heuristic (no new file read/edited in K iterations) + **consecutive-malformed-turn budget (~3)**; per-iteration **context budget check**: effective window read from `model.extra_params["num_ctx"]` (fallback: autosize/default — the models.py autosize fix helps only non-pinned setups; conaider pins 8192 so the loop check is the real mechanism), fixed headroom reserved, on pressure **evict oldest tool results** (replace with one-line stubs; always preserve system prompt + last K exchanges) with a visible warning; token counting always on stringified copies of tool-shaped messages, 0/exception counted as over-budget.
6. **History hygiene**: native tool dicts exist only in the in-flight loop; at loop end (and on KeyboardInterrupt) the transcript is rewritten as compact plain-text messages before `move_back_cur_messages` → summarizer/commit-context/sanity checks never see `role:"tool"` or `content=None`.
7. **Commit semantics**: track `edited_this_turn`; `allowed_to_edit` gating (dirty-commit of pre-existing user changes, create-file confirm) runs on **first touch per file only**; agent-touched files are exempt from later dirty checks; **edited files are NOT added to chat-files context** (tools re-read on demand — avoids 8k-window blowup); exactly **one `auto_commit(aider_edits=True)` per agent turn** over the accumulated set → `/undo` works, conaider gets one push per turn. Test: two edits to one file in a turn ⇒ one commit, `/undo` reverts it.
8. **Repo map reuse (explicit)**: AgentCoder builds its opening context through base `format_messages()`/`format_chat_chunks()` so `chunks.repo` flows in unchanged; `AgentPrompts` defines `repo_content_prefix`; map enabled for gemma3 via the conaider settings file (`use_repo_map: true` already in the template) — the fork's shipped defaults stay behavior-neutral for non-agent modes.
9. **GitLab via `python-gitlab` as an optional extra** (`aider[gitlab]`): healthy (v8.4.0, monthly), Python ≥3.10 matches. Local git (GitPython) does branch/commit/push; API does issue fetch, MR create, discussions. No "MR from issue" endpoint exists → branch `"<iid>-<slug>"` + configurable `Closes #<iid>` keyword; draft-MR-first UX. **Air-gapped rule**: runtime `check_pip_install_extra` becomes a graceful offline-aware error only; the real install is baked into the conaider image at build time (documented).
10. **Unsupported combos declared**: `--gui --agent` errors at startup (GUI's `st.write_stream` + confirm_ask don't fit the loop; conaider uses the terminal TUI only). A new `ModelSettings.tool_protocol` field (one-touch — `Model` copies fields dynamically, models.py:374-378) carries protocol hints; **not** `extra_params` (which leaks into every request in all modes).

## Phase 0 — Feasibility spike (GATE; build nothing else first)

`benchmark/agent_spike.py` (benchmark/ is excluded from the wheel) against live Ollama, **under production conditions**: `extra_params num_ctx=8192`, the actual draft agent system prompt + tool grammar + few-shot + repo-map-sized filler:
1. Confirm gemma3 `tools=` 400 on both `ollama_chat/` and `openai/…/v1`.
2. Text-protocol reliability on `gemma3:4b` and `:12b`: 30–50 trials over 5–6 multi-step tasks; measure fenced-block parse rate, correct-tool rate, argument fidelity, **false-stop/false-continue vs the done-convention**, task completion, with/without one reformat-retry; compare `tool_code`-style vs strict-JSON grammar; **measure degradation across iterations 1/5/10 — gate on late-iteration numbers**.
3. Native-mode sanity on one non-Chinese tools-capable model (`llama3.1:8b` or `gpt-oss:20b`): multi-turn tool history via both providers, **and verify effective context** (>2k-token transcript, assert no truncation via `ollama ps`/server logs) with `OLLAMA_CONTEXT_LENGTH` set.
4. **Gate**: gemma3:4b proceeds if late-iteration single-call validity ≥ ~80% (with retry) and multi-step completion ≥ ~60%; else recommend 12b or a tools-native non-Chinese model and **report back with numbers before building further** (per the brief). Results go into the integration doc.

## Phase 1 — Agent mode

**New files**
- `aider/coders/agent_coder.py` — `AgentCoder`; `send_message()` override (generator contract; per-iteration reuse of retry/backoff, exhausted→graceful stop, KeyboardInterrupt scrub; finally-block bookkeeping). Turn flow: stream/render text → strip reasoning → adapter extracts tool calls → finalize mdstream segment (empty-final guard) → permission gate → dispatch → `io.tool_output` events → append messages → budget/stall checks → resend; on loop end: scrub transcript, single `auto_commit`, lint/test hooks as usual.
- `aider/coders/agent_prompts.py` — system prompt (per adapter mode), tool docs, text grammar + few-shot, done-convention, error/retry templates, `repo_content_prefix`.
- `aider/agent/protocol.py` — `ToolCallAdapter` (native parser: index-keyed multi-call accumulation with ids; text parser: fenced header+payload, validation, reformat-retry; auto-detection).
- `aider/agent/tools.py` — schema registry (Draft7Validator) + dispatcher: `read_file`, `list_files`, `grep` (Python `re` over tracked files; offline-safe), `edit_file`, `write_file` (guardrails per decision 3), `bash` (own subprocess wrapper: capture, timeout, no TTY handoff — `run_cmd`'s pexpect path is unsuitable), `git` (allowlisted read-only via GitRepo), `done`.
- `aider/agent/permissions.py` — category policy over `confirm_ask`/`ConfirmGroup`.
- Tests: `tests/basic/test_agent_{coder,protocol,tools,permissions}.py`.

**Modified files**
- `aider/models.py` — additive `tools=`/`tool_choice=` kwargs on `send_completion` (legacy branch untouched); `ModelSettings.tool_protocol` field; num_ctx autosize accounts for tool schemas (minor correctness; real budgeting lives in the loop).
- `aider/coders/base_coder.py` — **additive `__init__` params only** for agent options (auto_accept_architect precedent).
- `aider/main.py` — thread agent params into `Coder.create`; `--gui --agent` guard; (Phase 2) `--gitlab-issue` batch hook next to `args.message` handling.
- `aider/coders/__init__.py` — +2 lines. `aider/args.py` — `--agent`, `--agent-max-iterations`, `--agent-tool-protocol`, `--agent-allow-shell`, `--agent-auto-approve-edits` (env/yaml free; regenerate sample.aider.conf.yml/sample.env).

**Order**: (a) plumbing + read-only tools + loop/budgets/scrub, mocked-litellm tests → (b) edit/write + permissions + commit integration + `/undo` test → (c) bash/git tools → (d) streaming polish + gemma3 text-mode hardening from spike data → (e) documented end-to-end demo on a scratch repo via Ollama.

## Phase 2 — GitLab issue-to-MR

**New**: `aider/gitlab.py` (config resolution; issue fetch; draft-MR create; discussions list/reply/resolve), `tests/basic/test_gitlab.py` (mocked). **Modified**: `aider/repo.py` (+`create_branch`/`checkout`/`push` thin GitPython wrappers with explicit error handling; commits always pass explicit fnames — empty `fnames` commits `-a`, repo.py:289), `aider/commands.py` (`cmd_gitlab_issue`), `aider/args.py` + optional-extras group `aider[gitlab]`.

Flow (`/gitlab-issue <iid>` or `--gitlab-issue <iid>` batch → `Coder.run(with_message=...)`): resolve URL/token (flags → `AIDER_GITLAB_*`/`GITLAB_TOKEN`/`GITLAB_PRIVATE_TOKEN`/`GITLAB_URL`/`CI_SERVER_URL`; **zero-config fallback: extract token + host from the `oauth2:<token>@` origin remote** — makes conaider work with no consumer changes; ssl-verify knob) → fetch issue → compose prompt → branch `aider/<iid>-<slug>` (configurable; reuse conaider's session branch if present) → run agent → push → **draft MR** with configurable `Closes #<iid>` → print URL. Phase 2b (stretch): `/gitlab-mr-feedback <mr_iid>` — unresolved threads → fix → push → reply in-thread → resolve; GitLab ops also registered as agent tools (`gitlab_*`, git-write permission category). **Future-work note (explicitly an idea, not scheduled)**: GitLab-as-context — `/gitlab-context <issue|wiki|mr>` pulling content into read-only context.

## Verification

- **Unit** (no LLM): text parser (malformed/multi-block/nested-fence/reasoning-contaminated/done-marker cases); dispatcher + schemas; edit_file tiers + failure text; permission matrix (incl. `--yes-always` × `explicit_yes_required`, double-prompt prevention); history scrub (summarizer-safe, token-countable); budget/stall/malformed-turn guards; commit semantics (two edits → one commit; `/undo`); mdstream empty-final guard. Mock via `@patch("litellm.completion")` (canned tool_calls / text-protocol content), `InputOutput(yes=True)`.
- **Integration**: scripted agent session on a temp git repo (edits applied, one commit, `/undo`, scrubbed history); mocked python-gitlab flow; full existing test suite green (no regression to default modes).
- **Live** (documented, not CI): Phase 0 spike vs local Ollama; agent-mode demo task on a real repo with `ollama_chat/gemma3`; issue-to-MR **run inside the conaider-tui container** (truest end-to-end; from the host use `GITLAB_URL=http://localhost:8080`, noting API-returned URLs reference `http://gitlab`).

## Risks

- gemma3:4b may miss the gate → that is the spike's purpose; report numbers + recommendation (12b / llama3.1 / gpt-oss) instead of building on sand.
- litellm 1.82.3 ollama_chat tool bugs → adapter rebuilds native history or uses `/v1` (with the context-length prerequisite); text path unaffected.
- Context pressure at 8k → eviction policy + stringified counting + write_file headroom checks, all unit-tested.
- Upstream drift → new modules; shared-file diffs limited to models.py / base_coder.py `__init__` params / main.py threading / args.py / coders/__init__.py.
